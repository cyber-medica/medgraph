# Кибермедика — Legacy URL Migration Policy v3

## Цель
Сохранить поисковый вес полезных исторических URL и не создавать soft-404/redirect-to-home patterns после миграции сайта.

## Решение по каждому старому URL

1. **Есть точный современный эквивалент товара/категории** → `301` на этот единственный эквивалент.
2. **Есть близкая, но не идентичная категория** → `301` допустим только если пользовательский смысл действительно совпадает.
3. **Товар окончательно удалён и эквивалента нет** → настоящий `404` или `410`; не редиректить на главную.
4. **Старый URL всё ещё приносит поисковый трафик** → приоритетно сопоставить вручную через Search Console / Яндекс Вебмастер.
5. **Параметрические/дублирующие URL** → canonical/redirect к основной версии только при подтвержденной эквивалентности.
6. **Stage/Preview/Tilda technical URLs** → никогда не включать в production sitemap.

## Запрещено

- массовый `301` всех старых URL на `/`;
- массовый `301` всех старых Product URL на `/catalog`;
- отдавать 200 с текстом «товар не найден»;
- сохранять старый URL в sitemap после редиректа;
- canonical со старой страницы на нерелевантную страницу;
- цепочки 301→301→200.

## Discovery после подключения Search Console / Яндекс Вебмастера

Собрать:
- страницы с показами/кликами за последние 16 месяцев;
- 404 и soft-404;
- redirect URLs;
- duplicate/canonical reports;
- исторические Tilda `tproduct` URL, если они ещё видны поисковику.

Для каждого URL создать mapping:
`old_url | traffic | backlinks/importance | new_exact_url | action | reason`.

## Acceptance
- один hop для каждого 301;
- целевой URL = 200;
- 404/410 отсутствующих товаров не маскируются редиректом;
- новый sitemap содержит только текущие canonical URLs;
- старые URL постепенно исчезают из индекса после обхода.
